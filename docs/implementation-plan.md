## 2. 里程碑明细

### M0：技术设计与评审

- 目标：在无应用代码情况下统一业务规则、数据模型、接口和验收。
- 任务：阅读AGENTS.MD及首轮参考图记录；完成八份设计；记录ORM/数据库冲突；自检状态、CAS、AI确认、引用和故障边界。
- 依赖：用户提供的任务书和参考图；无安装、无模型密钥要求。
- 交付物：technical-design、architecture、data-model、api-spec、state-machine、test-plan、implementation-plan、decisions。
- 验收：文档相互链接、规则无明显矛盾；用户明确批准设计与M1阻断决策；未决非阻断项有默认假设和解决阶段。
- 难点：既保留全部MVP需求又控制基础设施复杂度；兼容性未测不能写成事实。
- 风险：技术冲突已按本轮用户指令解决；该阶段当时的业务权限/核验策略未决风险已随Q03及本轮Q04—Q06解决；其他未决项按decisions §13处理。M0历史门禁不改变当前M2未授权边界。

### M1：工程骨架与依赖兼容验证

- 目标：一个能登录、调用API、连接真实数据库的最小系统，并证明关键依赖可运行。
- 任务：初始化Git和前后端；固定Python/Node/依赖版本及锁文件；错误/日志/request_id；SQLAlchemy UoW/Alembic；用户与Session；Argon2id、CSRF、角色骨架；同源代理和基础布局；Compose core（前端/API/MySQL/Worker/业务MinIO及桶策略初始化）；健康与配置校验；CI最小门禁。
- 依赖：M0明确批准；技术基线已确定，认证方案及Q03读取范围明确确认。
- 技术验证（由最新M1任务书收窄）：认证所需MySQL迁移/连接池/事务、基础MinIO、配置与Mock适配骨架；M1不部署Milvus/etcd/MinerU，不实现CRM CAS/状态机/完整审计，不调用真实模型。知识环境兼容验证归M4前置，真实Provider能力归对应AI里程碑。
- 交付物：可启动骨架、迁移、.env.example、.gitignore、README初稿、演示用户初始化、兼容性记录（版本/资源/命令/结果）。这些在批准后创建。
- 目标验收（非当前已完成声明）：core独立启动；认证/会话/配置与401/403/CSRF测试；MinIO持久化及桶权限负例；生产安全配置；空库迁移；锁文件安装、前端构建及同源认证。实际通过/未验证项见M1报告；8.0补充测试不能替代8.4。重依赖验证按最新范围后移，不虚构兼容结果。
- 难点：Windows WSL2、解析器依赖、MinIO共享配置与端口。
- 风险：硬件不足或模型下载不可达。处理：同一adapter接内部远程MinerU（需数据授权），或更换部署硬件；不能未告知就删掉PDF/Milvus需求。兼容性未解决不得宣称完整环境已就绪。

### M2：CRM与可靠性基础

- 目标：没有AI也能跑完整销售业务，并证明状态、权限、并发与审计正确。
- 任务：客户/联系人/商机/活动；经理负责人调整；五阶段固定概率与后端只读约束；证据上传/双人职责分离核验（角色+对象+操作权限）；单份成交依据原子选择且多候选可保存；LOST重开/WON拒绝；归档；可空预计金额、证据实际金额只读投影、Decimal与分币种Pipeline已知/未知计数；看板/列表/详情/表单；CAS/幂等命令/事务内审计；追加式审计访问；真实并发测试。
- 依赖：M1 core的真实MySQL/业务MinIO；Q04/Q05/Q06已批准，不再作为待决策阻断；Q05-A须在OTHER_APPROVED分支实现前确认，Q11/Q12仍在对应模块前确认；另需用户明确授权M2开发。不依赖knowledge。
- 交付物：可演示CRM、审计时间线、完整API文档、测试数据、并发/回滚报告、第一轮性能基线。
- 验收：创建客户到商机关闭/重开链路通过；25格状态矩阵；同version并发至多一次成功；audit插入失败全回滚；REP越权和终态编辑被拒；未知不转零；预计与实际不同仍可成交；WON实际统计取所选核验证据；币种不混加；证据不是未经核验bool；经理/ADMIN自核验及REP核验均拒绝；未知、金额/币种、重复/并发选择及只读概率覆盖F04—F06矩阵通过；核心E2E通过。这些是未来验收条件，本轮不执行。
- 难点：关联约束、锁序、decimal序列化、统计与列表口径。
- 风险：只写成功路径或前端隐藏代替授权；门禁必须包含直接非法API调用和真实数据库断言。

### M3：会议纪要解析、证据展示、人工审核与受控执行

- 目标：knowledge关闭时即可演示纪要→证据草稿→逐项确认→CRM/活动更新→审计的完整AI业务闭环。
- 任务：Provider/显式REAL与MOCK；Job租约恢复/AIRun；FACT/INFERENCE/UNKNOWN与片段定位；冻结changes/before/value/依赖组；审核/拒绝/放弃/重生成；apply/execution；权限/版本/context digest/状态/过期复检；建议行锁、商机CAS、活动唯一键、同事务review/execution审计和幂等；重复/冲突/失败UI。
- 依赖：已验收M2事务/并发/权限/审计与core；Q07字段边界、Q10保留策略决定。真实客户资料仅在Q09批准后使用；Mock/合成输入可先完成业务验收。不依赖Milvus/MinerU/RAG或embedding可用性。
- 交付物：可运行会议审核执行闭环、fixtures、标注集、Provider契约与并发/幂等/回滚报告；真实模型评测或明确未完成记录。
- 自动化与验收：I08—I10、C02—C05、E06—E08通过；生成/未确认不更新；只执行选择的合法项；过期/旧版本/旧上下文拒绝；重复无额外活动；审计失败全回滚；REAL失败不转Mock；只启core仍完成闭环。
- 难点：语义与Schema边界、部分选择依赖、失败状态与事务关系、权限竞态。
- 风险：只做解析页面或ACCEPTED悬挂；禁止把执行推迟M5或人为依赖未交付RAG。

### M4：企业知识库

- 目标：完成真实上传、解析、向量索引、带引用问答与安全删除闭环。
- 任务：TXT/MD/PDF限制；MinerU归一化；revision/chunk/generation；embedding与Milvus；READY发布；Top-K/阈值校准；引用定位；版本更新；删除与对账；RAG问答异步任务；失败/空文档/无结果UI。
- 依赖：M3 Job/Provider；M4前完成Milvus/etcd/共享MinIO/MinerU兼容性与资源验证，M1不声称已部署这些后续服务。
- 交付物：可运行知识库、解析样本、索引profile、RAG标注集与评测、跨系统故障恢复说明。
- 自动化与验收：I15—I17、F02/F03、E09及D03/D04通过；关闭knowledge不影响core/M3；真实PDF能定位页与原文；失败明确；无结果拒答；向量残留也不能返回删除文档；重建失败保留旧版；新embedding整库切代不混维；检索和引用门槛通过。
- 难点：扫描/表格质量、模型资源、跨系统无ACID。
- 风险：PDF质量不达标或共享MinIO故障；分别报告适用边界、资源和恢复，禁止静默返回“解析成功”。

### M5：CRM、活动与RAG的增强型跟进建议

- 目标：结合商机、活动、知识生成可解释行动，复用M3已验收的人工审核执行。
- 任务：授权上下文组合、冻结activity digest/引用revision/generation；理由/缺失信息/风险/时间/优先级；FACT与advisory分离；引用复核、来源删除失效、知识关闭故障UI；复用apply事务/幂等/审计，不另建执行系统。
- 依赖：M2可靠性、M3已完成受控执行、M4已验收RAG；真实资料需Q09批准。
- 交付物：可运行增强建议、带引用演示、模型效果与安全回归报告。
- 自动化与验收：引用来自实际授权召回；无依据明确缺失，不推断成交；活动变化/引用不可用拒绝危险应用；不同键无重复；关闭knowledge禁用增强生成但不影响CRM/会议apply；回归M3权限/事务/幂等矩阵及E06—E11适用项。
- 难点：多来源有效性、引用支持和相关性、推断边界。
- 风险：来源失效绕过缓存、增强功能扩权；执行服务保持唯一入口、复核来源、独立评估质量。

### M6：质量、部署与作品集交付

- 目标：完整系统在新环境可启动、可测试、可恢复，并能解释技术取舍。
- 任务：全量回归；真实AI评测；性能基准；资源限制与负载；OpenAPI/README/部署/备份恢复；合成demo seed；演示脚本；依赖漏洞检查；实际交付版本和已知限制；项目复盘。
- 依赖：M1—M5验收；真实模型密钥/硬件或明确标识的演示限制。
- 交付物：锁版本Compose、CI报告、测试/评测结果、恢复演练、演示数据与操作说明、架构决策最终状态。
- 验收：新机器依README复现；全部必需服务启用；MVP测试矩阵通过；恢复核验无二次执行；无默认生产密码/公开数据库/敏感日志；真实与Mock报告区分；不把未验证性能/可用性作为承诺。
- 难点：依赖体量、模型成本、真实环境与CI差异。
- 风险：为演示临时绕过规则；禁止放宽状态/权限/人工确认，宁可明确列未完成验收。

## 3. 工作量估算与范围控制

不在未知开发熟练度、硬件与供应商条件下承诺日期。M0评审后，M1用真实spike建立估算；每阶段拆为1—3天可验证的小任务，估算只包含明确验收与测试，模型/解析环境单列缓冲。任何变更影响模型、状态机、API或权限时，先更新ADR和相关文档，再开发；不以“先跑起来”为由删审计/事务/并发测试。

可后置的增强：拖拽、录音/会议平台集成、通知、图中增长率、客户级AI自动更新、完整合同审批、SSO、混合检索、队列、HA。不可后置为“最终补充”的核心：后端权限、CAS、事务内审计、人工确认、REAL失败显式报错、删除可见性过滤。

## 4. 阶段证据模板

每阶段提交：目标与完成范围；可复现启动/验收步骤；实际版本与环境；测试通过/失败/未跑列表；已知限制与残余风险；数据/迁移影响；下一阶段依赖。用户批准M0仅授权进入约定的开发阶段，不意味着自动部署、对外发信或上线真实客户数据。
