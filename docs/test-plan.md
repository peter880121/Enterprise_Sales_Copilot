## 1. 原则、分层与环境

先证明业务正确，再验证模型效果与页面行为。领域单测最多、真实数据库API集成居中、浏览器E2E覆盖关键闭环；不以覆盖率数字替代核心断言。所有已承诺的不变量与故障用例必须通过，关键规则覆盖分支包含正反两面。AI Mock只验证业务/协议，真实模型报告独立，不能用Mock成绩声称模型可靠。

## 4. 并发与故障的可复现测试

### C01：同版本双请求

建一个NEGOTIATION、version=7商机。两个独立连接在barrier后分别改金额和日期，expected_version均7。收集完整响应和提交结果：恰一个200（若无外部注入故障），另一个409；最终version=8，字段等于单一成功请求，不能混合；只有一个版本8主mutation审计。重复不同调度至少20次，不以sleep决定正确性。另测状态变更与普通PATCH、归属调整与AI应用竞争。

### C02：审计失败必须回滚

在真实MySQL事务内完成CAS后，注入repository audit INSERT异常（或使用测试专用约束/权限拒绝）并让事务退出。新连接确认stage、amount、version与调用前相同，AuditEvent没有成功事件，IdempotencyRecord无完成结果。AI apply同样验证Activity零新增、suggestion仍DRAFT/单独失败信息、无execution_id。不是只断言mock rollback被调用。

### C03：过时建议

base_version=3生成草稿，另一用户更新为4；apply仍携带3：409 SUGGESTION_STALE，无CRM/活动写入；后续状态为STALE。另用新增/编辑/完成Activity改变context_digest但不改商机version，仍须拒绝。生成期间发生变更、到期边界、客户端篡改expected版本亦测。

### C04：重复与响应丢失

两个连接同key同时关闭/重开/apply；成功结果一致，version仅+1、主审计唯一、Activity唯一。commit后故意丢弃HTTP响应，再以原key重试返回原结果。相同key不同body409；不同key同已执行建议相同选择返回原结果，改变选择409；换账号不能读他人缓存。超过幂等保留期后版本仍防同次旧命令重做，AI仍永久防重复活动。

### C05：数据库锁/身份竞态

制造deadlock/锁超时，验证有限回滚重试及错误code；用户停用/角色变更与apply并发，要么先完成合法操作，要么拒绝，不能在停用后执行；两个ADMIN同时停用彼此后至少一个有效ADMIN。客户停用与新建开放商机竞争，不能同时得到“已停用客户+新开放商机”。

### F01：模型与embedding故障

可控HTTP端依次返回超时、429带Retry-After、503、401、非法JSON、合法JSON但额外字段、错误引用、错误维度。断言连接/请求/总预算、调用次数上限、退避、AIRun计数、Job失败明确、无静默Mock或CRM写入。使用加速可控时钟测试预算，不令CI实际等待分钟。

### F02：解析/文件故障

固定PDF包含：原生文本、扫描页、跨页表格、中文、空白、损坏、密码保护、超100页、伪MIME；TXT含空白、非法编码、MD含恶意HTML。断言明确错误/质量限制；MinerU异常/超时进Job失败，不返回空READY；资源限制触发仍可服务CRM。PDF真实解析样本至少一项在所锁MinerU环境运行，不用纯Mock替代解析验收。

### F03：跨系统最终一致性

在“MinIO写后DB提交前”“Milvus upsert后发布前”“发布后旧代清理前”“删除标记后外部清理前”分别杀worker。重启后租约可接管，确定性键/代标识去重；发布指针不指向半成品；旧/删除内容绝不泄露；孤儿在对账窗口内清理并记录。把过期worker暂停后恢复，确认lease_token失效不能发布/覆盖新结果。

## 5. AI评测集与发布门槛

### 5.1 数据集

会议纪要至少40条人工标注合成样本：明确事实、预算未确认、无预算、模糊日期、矛盾金额、多联系人、英文/中文、无成交意图、恶意指令等。字段级标注value、FACT/INFERENCE/UNKNOWN和证据区间；双人复核如人力不足则记录单人标注局限。拆开发集与冻结验收集，禁止只在同一集调prompt和报告成绩。

RAG至少40问：20可回答（其中至少5跨块）、10无答案、5版本/删除情景、5注入/越权情景；预标相关文档/页/块和应答要点。资料采用原创合成产品、政策与方案，不输入真实企业秘密。答案/引用质量人工评分加确定性校验。

### 5.2 建议门槛（待M3/M4实测确认）

| 指标 | 发布目标与限制 |
| --- | --- |
| 可持久化结构结果 | 后端严格Schema通过率100%，不合格算失败而非“成功但缺字段” |
| 模型首次Schema合格率 | ≥95%，报告修正后率与失败数，不能藏失败 |
| 会议关键事实精确率 | ≥95%；金额/日期/决策人分别报告，不由总平均掩盖 |
| 无依据关键字段提议 | 验收集0例；不等于对未来输入零幻觉保证 |
| 引用结构有效率 | 100%（必须实际检索来源/合法区间） |
| 引用内容支持率 | 人工≥90%，报告部分支持与错误支持 |
| 检索Recall@8 | 可回答样本≥90%，检索与生成分开计分 |
| 无答案正确拒答 | ≥90%，错误自信回答单独列出 |
| 注入/未经确认写入 | 安全验收集越权成功0例；数据库断言无副作用 |

记录模式、provider/model、embedding维度、prompt/schema/chunker/阈值版本、输入hash、耗时、tokens、费用估算、原始得分和失败案例。阈值根据开发集校准，在冻结集验收；不把自报confidence当正确率。模型/解析器/prompt变更需回归，Mock不参与真实质量门槛。没有真实API时可交付Mock业务闭环，但真实模型验收标“未完成”，不能声称完整真实AI演示达标。

## 7. 性能、恢复与CI门禁

M2基准：记录硬件/容器资源/版本，种1万商机、多个客户/联系人、10并发跑5分钟，测列表、详情、汇总p50/p95/错误率及EXPLAIN；CRM p95≤500ms为验证目标，失败需剖析/整改，不能先承诺生产性能。AI延迟单独统计，不能混入同步CRUD指标；文件与向量规模在M4逐级增量测，不承诺GPU吞吐。

恢复演练：新环境还原MySQL和MinIO manifest，恢复期间禁止worker清理，核对文件hash/证据/审计版本；向量从chunk重建，切换前不可READY；执行过的建议重放不新增副作用。记录备份时间点、实际恢复耗时、缺失范围；单机每日备份不等于PITR或HA保证。

CI顺序：静态/单元→真实MySQL迁移与集成→前端组件/构建→核心E2E→相关知识集成；真实模型因成本/密钥独立手动或受控发布任务，但发布质量报告必需。任何核心规则/事务测试失败阻止合并；flake不通过反复rerun掩盖，修复并记录原因。CI产出JUnit、覆盖分支报告、OpenAPI差异、E2E失败trace（脱敏），不保存cookie/真实纪要/密钥。
